เอกสารนี้สรุปกติกาการเขียนบทเรียนให้ตรงกับสัญญา "10 นาที" และมาตรฐานคุณภาพใน [PLAN.md](../PLAN.md)

## 2. งบเวลา 10 นาที (PLAN.md ข้อ 3.1)

| ช่วง | เวลา | เขียนอะไร |
|---|---|---|
| Hook | 0:00–0:45 | 60–100 คำ เกี่ยวเรื่องเล่า/คำถามชวนคิด/สถิติที่ทำให้อึ้ง — **ห้ามเปิดด้วยนิยาม** |
| แก่น 3 beats | 0:45–5:30 | 3 ท่อน ท่อนละ ~150–200 คำ |
| หลักฐาน | 5:30–6:30 | สรุปที่มา + ข้อจำกัด |
| ลองทำวันนี้ | 6:30–7:30 | 1–3 ข้อ ทำได้จริงใน 5 นาที |
| ควิซ | 7:30–9:30 | 4 ข้อ (สุ่มจากคลัง 8–10 ข้อ) |
| ปิด + แนะนำต่อ | 9:30–10:00 | สรุป 1 ประโยค |

**กติกาจำนวนคำ (บังคับ):** ผลรวมข้อความที่ผู้เรียนอ่านจริง (hook + beats + evidence.summary +

คำนวณแบบไทยด้วยฮิวริสติก "จำนวนอักษรไทย ÷ 4.5" บวกคำอังกฤษที่นับจากช่องว่าง — ดู
[src/lib/readingTime.ts](../src/lib/readingTime.ts) ถ้าเขียนคำอังกฤษ/ตัวเลขปนเยอะ ตัวเลขจะคลาดเคลื่อนได้บ้าง
ให้ยึดตัวเลขที่ `validate-content.ts` รายงานเป็นหลัก ไม่ใช่กะเอง

## 3. หกรูปแบบบทเรียน — เลือกให้เหมาะกับเนื้อหา ไม่ใช่สุ่ม

| format | ใช้เมื่อ... | โครง 3 beats ที่แนะนำ |
|---|---|---|
| `story` | มีเหตุการณ์/เคสจริงที่เล่าได้เป็นเรื่อง | เกิดอะไรขึ้น → ทำไมถึงเป็นแบบนั้น → ถอดเป็นบทเรียน |
| `classic` | เป็นแนวคิด/โมเดลที่อธิบายตรงไปตรงมาได้ | หลักการคืออะไร → ตัวอย่างประกอบ → เอาไปใช้อย่างไร |
| `myth-bust` | มีความเชื่อผิดที่พบบ่อยเรื่องนี้ | เชื่อกันว่า... → หลักฐานบอกว่า... → ของจริงคือ... |
| `playbook` | มีสถานการณ์ที่ต้องการ "สคริปต์" ใช้ทันที | สถานการณ์ → ขั้นตอน/สคริปต์ → กรณีที่ต้องระวัง |
| `decode` | เป็นทักษะอ่านสัญญาณ/ตีความคน | ให้สถานการณ์ชวนตีความ → เฉลยหลักจิตวิทยา → นำไปสังเกตต่อ |
| `versus` | คนสับสนสองแนวคิดที่คล้ายกัน | แนวคิด A คืออะไร → แนวคิด B ต่างกันตรงไหน → เลือกใช้เมื่อไหร่ |

**กติกาจัดคิว:** เมื่อเลือกหัวข้อ 2 บทในหมวดเดียวกัน พยายามให้ format ต่างกัน
เพื่อให้อัลกอริทึมเลือกบทประจำวัน ([src/lib/dailyPicker.ts](../src/lib/dailyPicker.ts)) มีตัวเลือกที่ดีขึ้น

## 4. หลักฐาน (evidence)

- `summary` อธิบายที่มาแบบอ่านง่าย ไม่ใช่ citation แบบวิชาการ
- `caveat` **บังคับใส่** ถ้างานวิจัยนั้นมีข้อโต้แย้ง, replicate ได้ไม่เต็มร้อย, หรือ effect size
  แตกต่างกันมากตามบริบท (พบได้บ่อยในจิตวิทยา) ถ้าไม่แน่ใจว่าต้องใส่ไหม ให้ใส่ไว้ก่อน
  ปลอดภัยกว่าการฟันธงเกินหลักฐาน — ดูตัวอย่างที่ดีใน `e01-testing-effect-myth.ts`
- `sources` อย่างน้อย 1 รายการ ควรมีชื่อผู้วิจัย/นักเขียนตัวจริงและปีถ้าทราบ
  ห้ามกุดัวเลข/ชื่อ ถ้าไม่แน่ใจปีให้เว้นว่างไว้ดีกว่าใส่ผิด

## 5. ลองทำวันนี้ (tryToday)

1–3 ข้อ แต่ละข้อต้อง **ทำเสร็จได้ในการนั่งเดียว ≤5 นาที** และมี "จุดเช็ค" ว่าทำสำเร็จหรือยัง
(ไม่ใช่คำแนะนำเชิงนามธรรมแบบ "จงมีสติมากขึ้น")

## 6. คำถามควิซ (questions)

- คลังคำถาม **8–10 ข้อต่อบท** (ระบบสุ่ม 4 ข้อ/รอบ)
- สัดส่วนชนิดคำถามโดยประมาณ: `mcq` 40% · `scenario` 35% · `true-false-why` 15% · `odd-one-out` 10%
  (กับคลัง 8 ข้อ คือประมาณ mcq 3, scenario 3, true-false-why 1, odd-one-out 1)
- **ทุกตัวเลือกต้องมี `explain`** ที่บอกว่าทำไมถูกหรือทำไมผิด แม้แต่ตัวลวงก็ต้องอธิบาย
  ไม่ใช่แค่ตัวถูก
- เลี่ยงคำถามท่องนิยาม ให้เขียนเป็นสถานการณ์ที่ต้องเลือกการกระทำ (`scenario`) ให้ได้สัดส่วนมากพอ
- ใส่ `targetBeat` (index ของ beats ที่ข้อนั้นวัด) เมื่อคำถามผูกกับ beat ใด beat หนึ่งชัดเจน
  ระบบใช้ค่านี้พาผู้เรียนกลับไป "เรียนซ้ำ" ที่จุดที่ตอบผิดโดยตรง — เว้นว่างได้ถ้าคำถามวัดภาพรวม/evidence

## 7. tags และ relatedIds

- `tags` 4–6 คำ ใช้คำที่คนน่าจะค้นหาจริง (ระบบค้นหาใน Phase 4 จะพึ่งฟิลด์นี้)
- `relatedIds` ใส่ 2–4 id **ต้องมีอย่างน้อย 1 id ที่ขึ้นต้นด้วยตัวอักษรหมวดอื่น** (ข้ามหมวด)
  เพื่อให้ระบบแนะนำ ([src/lib/recommend.ts](../src/lib/recommend.ts)) พาผู้เรียนไปหมวดอื่นได้
  ใส่ id ของบทที่ยังไม่ถูกเขียนได้ (เผื่อแผนในอนาคต) แต่ควรตั้งชื่อให้ตรงรูปแบบข้อ 1 เพื่อให้ผูกได้ทันทีที่เขียนจริง

## 8. ethicalNote

**บังคับ** สำหรับทุกบทในหมวด `read-people` (b) และ `relationships` (d)
เพราะเป็นหมวดที่เสี่ยงถูกใช้ในทางบงการ/ไม่เคารพอีกฝ่าย เขียนสั้นๆ ว่า "เส้นที่ไม่ควรข้าม" ของเทคนิคนั้น
หมวดอื่นใส่หรือไม่ใส่ก็ได้ตามความเหมาะสม
